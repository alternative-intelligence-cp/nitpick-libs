# 0.2.1 — the worker skill, and the record check — PLANNED

> The worker is the role that does the work, and the current skill cannot be
> dispatched from the workbench: every path in it assumes the session started
> inside the library. This subcycle rewrites it around one argument, `REPO`,
> defines the report block the loop reads, and writes the script that checks a
> committed record mechanically — with a control that proves the script can
> fail.

`skills/worker/SKILL.md` (4 KB, six sections) and `skills/check/scripts/`.
0.2.0 is DONE: W-15…W-25 exist, and the board has the in-flight table. The
research paragraph in §3 below is a placeholder until 0.2.3 writes the

## 2. Decisions

P-1, P-2, P-3, P-6, P-13, P-16. Two local ones:

- **L-1 — the record's REPORT block omits its own commit hash.** The report
  is committed *in* the subcycle's commit, so it cannot name that commit.
  The block lists earlier commits by hash and the last as `HEAD`; the final
  message adds the actual hash; `check_record.py` checks that `HEAD`'s subject
  begins `cycle <id>:`. *Declined:* a second "record" commit after the work
  commit (breaks one-commit-per-subcycle and doubles the history).
- **L-2 — the RUNNING status is not committed on its own.** The worker edits
  the title line to `RUNNING` at start and to `DONE` at the end, and both
  land in the subcycle's one commit. A killed worker therefore leaves an
  uncommitted `RUNNING` line, which is exactly the evidence the recovery
  procedure wants.

## 3. The new `SKILL.md`, section by section

Frontmatter: keep `name`, `description` (add "dispatched by the orchestrator
with a REPO argument"), `argument-hint: "[repo] [subcycle]"`, and extend
`allowed-tools` with `Bash(cmp *)`, `Bash(sha256sum *)`, `WebFetch`,
`WebSearch` — pre-approval only; the tool *set* is the agent definition's
(0.2.4).

**§1 Inputs.** The prompt that dispatched you carries these lines, and every
one is required. If any is missing, stop and report `BLOCKED` with
`for-the-author: missing input <name>`:

```
STREAM: sN
REPO: <absolute path of the repository root>
SUBCYCLE: <cycle>.<sub>          e.g. 0.0.0
TOOLCHAIN: NPKC=<abs> NPKRT=<abs> COMMIT=<compiler commit>
ATTRIBUTION: <the trailer lines, verbatim, one per line>
TREE: clean | dirty
AUDIT: none | <absolute path of an audit report to triage>
DIGESTS: none | <absolute paths of research digests to file and cite>
NOTES: none | <free text from the orchestrator: a verifier FAIL, a predecessor's death, an answer from the author>
```

Define `WB` as the workbench root (`REPO/..` for a library,
`REPO/../../nitpick-libs` for an application). Every path below is absolute
and built from `REPO` or `WB`. **Every git command is `git -C "$REPO" …`**,
because your shell starts in the workbench, and a bare `git commit` there
commits to the wrong repository — the workbench ignores the library trees, so
it would commit nothing you meant.

**§2 Before touching anything.**

1. The claim: `grep -n '`<repo-name>`' "$WB/BOARD.md"` must show a line
   containing `CLAIMED <your stream>`. Anything else → stop, report
   `BLOCKED`, `for-the-author: claim mismatch`.
2. The tree: `git -C "$REPO" status --porcelain`. If `TREE: clean` was
   promised and this is non-empty → stop, report `BLOCKED`. If `TREE: dirty`,
   read `git -C "$REPO" diff` and the subcycle file's execution record first:
   a predecessor died here. Continue its work or `git stash` it with a
   message naming the subcycle, and say which in the record.
3. The toolchain: `"$NPKC" --version` (or whatever the compiler answers to)
   runs, and `sha256sum "$NPKC" "$NPKRT"` matches
   `$WB/.internal/toolchain/<COMMIT>/SHA256SUMS`. Mismatch → `BLOCKED`.
4. The compiler at `REPOS/nitpick` is read-only. The workbench is read-only
   *for you* (W-16). You write under `REPO` and nowhere else.

**§3 Read, in this order** — all absolute:

`$WB/PLAYBOOK.md` (for an application also `$REPO/../PLAYBOOK.md`);
`$REPO/CLAUDE.md`; `$REPO/meta/specs/SAFETY.md`, then the specification the
subcycle names; `$REPO/meta/DECISIONS.md`; `$REPO/meta/roadmap/<cycle>/README.md`;
`$REPO/meta/roadmap/<cycle>/<subcycle>.md`. If `DIGESTS` names files, read
them after the specification they concern. If `AUDIT` names a report, read it
last and triage it in §7.

**§4 Start.** Change the subcycle file's title line to
`— RUNNING (since <date>, <stream>)`. Do not commit that alone (L-2).

**§5 The discipline.** Keep every current bullet (one commit per subcycle
under a green run; the specifications are the authority; a settled decision is
superseded; never work around a compiler defect; verify language claims
against the compiler's source; `--only` iterates). Add:

- **Long commands.** The shell tool stops at ten minutes and moves most
  commands to the background at the cap — but not `git`. Anything you expect
  to run more than a few minutes — a full harness, a forty-times stress run —
  is started in the background and polled. A timeout is not a red; a red is a
  red.
- **External facts.** When the work needs a fact about the world outside the
  compiler tree — a release number, a standard's text, a known defect in prior
  art — one fetch may be done inline. More than one, or anything
  security-sensitive, is a research request to the researcher agent: write
  the request in the shape the research skill defines and dispatch it. File
  the digest it returns under `$REPO/meta/research/` yourself; the researcher
  never writes here. Language facts are never looked up on the web.
  *(cross-reference: `skills/research/SKILL.md` — written by 0.2.3)*
- **A compiler defect** stops you. Record the reproduction under
  `$REPO/tests/probe/` or `$REPO/meta/scratch/` with the exact command and
  diagnostic, set status `STOPPED`, fill `compiler-defect:` with the path.
- **A decision you need that is not in `DECISIONS.md`** is `NEEDS-DECISION`,
  with the question and your recommendation in `for-the-author:`. Do not
  guess.

**§6 Before every commit.**

```bash
python3 "${CLAUDE_SKILL_DIR}/../check/scripts/check_refs.py" "$REPO"
```

Clean, or the commit does not happen. Commit with
`git -C "$REPO" add -A && git -C "$REPO" commit -F "$msgfile"` where the
message subject is `cycle <cycle>.<sub>: <what>` and the body says **why**.
End the message with the `ATTRIBUTION` lines exactly as given. Never write a
model name yourself.

**§7 Closing a subcycle.**

- [ ] the subcycle's checklist items in the cycle README ticked, or struck
      with a reason
- [ ] the execution record appended: what was done, what was found, what it
      cost, and the REPORT block (§9) as its last entry
- [ ] the title line set to `— DONE (<date>)`
- [ ] if this is the cycle's **last** subcycle and `AUDIT: none`: stop before
      the close steps and report `READY-TO-CLOSE` instead of `DONE`. The
      orchestrator will dispatch the auditor and re-dispatch you with the
      report. If `AUDIT` names a report: triage every finding — fixed, or
      declined with a reason, in the record — then run the close checklist
      below.
- [ ] `check_refs` clean; committed; tree clean

**§8 Closing a cycle** (only with an audit report in hand): the current
checklist, unchanged — every item ticked or struck, the gate re-read, findings
in the record, decisions recorded and questions struck through with their
numbers, the next cycle's opening subcycle file written execution-grade **by
you, now**, the cycle moved to `meta/roadmap/done/`, `ROADMAP.md` updated,
`check_refs` clean. Then report `DONE`.

**§9 The REPORT block.** Your final message is this block and nothing else
above it; the same block is the last entry of the execution record.

```
REPORT <repo-name> <cycle>.<sub>
status: DONE | READY-TO-CLOSE | BLOCKED | STOPPED | NEEDS-DECISION | RED
stream: sN
model: <the model id your system prompt names>
toolchain: <COMMIT>
commits:
  - <hash> <subject>            (earlier commits this subcycle, if any)
  - HEAD <subject>              (in the record) / <hash> <subject> (in the message)
harness: <exact command> -> <its summary line verbatim>
         | not run: <reason>   (before 0.0.2 the harness does not exist; list the probe commands and their exit codes instead)
check: clean | <n> findings
record: <path of the subcycle file> — <its title status>
next: n/a | <path of the next subcycle file written execution-grade>
findings-for-playbook: none | - <one line each>
open-questions-raised: none | <ids>
for-the-author: none | - <one line each, with a recommendation>
compiler-defect: none | <path of the reproduction>
tokens-and-time: <what your harness notice reports, if anything> 
```

`for-the-author` is the stop list: a compiler defect, a decision not in
`DECISIONS.md`, a specification wrong in a way that changes a plan, a
contested repository, a negative probe that questions a repository's shape,
an ambiguity you would otherwise guess at.

## 4. `check_record.py`

`skills/check/scripts/check_record.py <repo> <cycle>.<sub>`. Exit 0 clean, 1
findings, 2 could not run. Findings, each a line `[kind] detail`:

| Kind | Check |
|---|---|
| `no-file` | `<repo>/meta/roadmap/<cycle>/<cycle>.<sub>.md` does not exist |
| `bad-status` | the title line's status is not `PLANNED`, `RUNNING (…)` or `DONE (…)` |
| `no-report` | the `## Execution record` section holds no `REPORT <name> <id>` block, or the last one names a different repository or subcycle |
| `missing-field` | a required key of the block is absent (every key in §9 above) |
| `bad-report-status` | the status value is outside the six |
| `status-mismatch` | report `DONE`/`READY-TO-CLOSE` with a title not `DONE`, or report `RUNNING`-class (`BLOCKED`, `STOPPED`, `NEEDS-DECISION`, `RED`) with a title `DONE` |
| `unknown-commit` | a hash listed under `commits:` that `git -C <repo> cat-file -e <hash>` rejects |
| `head-subject` | `HEAD`'s subject does not begin `cycle <cycle>.<sub>:` when the status is `DONE` or `READY-TO-CLOSE` |
| `dirty-tree` | `git -C <repo> status --porcelain` is non-empty |
| `unticked` | status `DONE` and an unticked, unstruck item under the subcycle's `###` heading in the cycle README |

Parsing rules: the title line is line 1; the status is the text after the
last ` — `; the REPORT block runs from a line starting `REPORT ` to the next
blank line; keys are `^\s*([a-z-]+):`; the README's subcycle section runs
from `^### <cycle>.<sub>` to the next `^###` or `^## `, and an item is
`- [ ]` (unticked), `- [x]` (ticked), or `~~` anywhere on the line (struck).

## 5. The control — `skills/check/scripts/test_check_record.py`

Builds a throwaway repository in a temporary directory (`git init`, a
`meta/roadmap/0.0/README.md` with a `### 0.0.0` section, a `0.0.0.md`, one
commit), then mutates it once per finding class and requires the script to
report **exactly** that class, plus one fully-correct case that must be clean.
Ten cases, ten expected outcomes. It runs in under five seconds and it runs
first in 0.2.7's dry run.

## 5b. The control `check_refs.py` already claims

`skills/check/SKILL.md` says the script *"has a negative control: it is known
to catch all six classes"*. There is none in the tree. The first flagless
test session built one ad hoc and every class fired; it disappeared with
that session's temporary directory. Make it permanent as
`skills/check/scripts/test_check_refs.py`, the same shape as
`test_check_record.py`: a throwaway repository under a temporary directory
with one planted fault per class — a broken link, a duplicated decision, a
cited-undefined, a defined-uncited, an undefined question, a leaked home
path — plus one clean case. Seven expected outcomes, exact. It runs first in
0.2.7's dry run beside the other controls, and the sentence in `SKILL.md`
names the file.
