# 0.2.4 — the agent definitions — PLANNED

> A skill's `allowed-tools` pre-approves and never restricts, so "the auditor
> reports and never fixes" and "the researcher never writes" have been
> discipline only. An agent definition's `tools:` list is exclusive, its
> `skills:` field preloads a skill's full content, and the orchestrator can
> dispatch by agent type instead of asking each fresh agent to load a skill
> and hoping it does. This subcycle writes the five roles as agents.

## 1. Where you are

`agents/` does not exist; `.gitignore` already un-ignores it. The five skills
the agents preload exist (0.2.1–0.2.3). The orchestrate skill (0.2.2) dispatches
by the names below.

## 2. Decisions

P-9, P-14, P-17. Local:

- **L-1 — the verifier's procedure lives in its agent body, not a skill.**
  It has one user. The mechanical half (`check_record.py`) is in the check
  skill, which the verifier preloads. *Declined:* a seventh skill.
- **L-2 — every agent that may need to look something up lists `WebFetch`
  and `WebSearch` explicitly**, because `tools:` is exclusive and omitting
  them removes research silently. The auditor and researcher need them for
  their own work; the worker and planner need them for the inline threshold.
- **L-3 — the worker and the planner keep `Agent`**, so they can dispatch
  the researcher (nesting is allowed three deep). The auditor, verifier and
  researcher do not: nothing they do fans out.

## 3. The five files

The `skills:` value is `worker` (bare) in the first attempt; step 2 below
tests whether the plugin namespace is needed and the outcome is recorded
and applied to all five.

`agents/worker.md`
```
---
name: worker
description: Works one subcycle of a Nitpick ecosystem repository, exactly as dispatched by the orchestrator with the dispatch template. Do not use for anything else.
skills: [worker]
tools: Read, Write, Edit, Grep, Glob, Bash, Skill, Agent, WebFetch, WebSearch
model: inherit
---
You are a worker in the Nitpick ecosystem. The worker skill above is your
procedure; your prompt carries the inputs it requires; your final message is
the REPORT block and nothing else. You write only under REPO.
```

`agents/planner.md`
```
---
name: planner
description: Writes an execution-grade plan for a Nitpick ecosystem cycle or repository, as dispatched by the orchestrator. Never writes code.
skills: [plan, research]
tools: Read, Write, Edit, Grep, Glob, Bash, Skill, Agent, WebFetch, WebSearch
model: inherit
---
You are a planner in the Nitpick ecosystem. The plan skill is your procedure
and the research skill is how you check the outside world. Your prompt names
the repository and the cycle. You write only under that repository. Your
final message is a REPORT block with status DONE, BLOCKED or NEEDS-DECISION.
```

`agents/auditor.md`
```
---
name: auditor
description: Adversarially audits a Nitpick ecosystem repository or the whole ecosystem and REPORTS without fixing. Cannot write files.
skills: [audit]
tools: Read, Grep, Glob, Bash, Skill, WebFetch, WebSearch
model: inherit
---
You are an auditor. The audit skill is your procedure. You have no file-writing
tools on purpose (A-1); if you find yourself needing one, that is a finding,
not a task. Your final message is the report in the audit skill's format, and
the orchestrator files it. Do not run any command that modifies a repository.
```

`agents/verifier.md`
```
---
name: verifier
description: Independently verifies a worker's report against the committed tree before the orchestrator releases or advances a claim. Read-only plus running the harness.
skills: [check]
tools: Read, Grep, Glob, Bash
model: sonnet
---
You verify. Your prompt carries REPO, SUBCYCLE, TOOLCHAIN and the report's
harness line. Run, in order, and stop at the first failure only to report it:
1. `git -C "$REPO" status --porcelain` is empty
2. `git -C "$REPO" log -1 --format=%s` begins `cycle <SUBCYCLE>:`
3. `python3 <check skill dir>/scripts/check_refs.py "$REPO"` exits 0
4. `python3 <check skill dir>/scripts/check_record.py "$REPO" <SUBCYCLE>` exits 0
5. the harness line: run the exact command from the report in the background
   if it may exceed a few minutes, capture its summary line, and compare it
   byte for byte with the reported one. Before the harness exists (0.0.0,
   0.0.1) the record lists probe commands and exit codes: run each with the
   TOOLCHAIN paths and compare exit codes.
Final message: `VERIFY <repo> <SUBCYCLE> PASS` or `FAIL`, then one line per
step with what was run and what came back. Nothing else. You write nothing.
```

`agents/researcher.md`
```
---
name: researcher
description: Answers one RESEARCH REQUEST about the world outside the compiler tree with a dated, sourced digest. Never writes files.
skills: [research]
tools: WebSearch, WebFetch, Read, Grep, Glob
model: inherit
---
You research. The research skill is your procedure. Your prompt is one
RESEARCH REQUEST in the skill's shape; stop at its budget. Your final message
is the digest in the skill's shape and nothing else. You never write a file:
the requester files the digest.
```

## 4. The steps

1. Write the five files.
2. Start a session in the workbench with the plugin loaded and read the
   "available agent types" listing the harness prints: the five must appear,
   and their exact names (expected `npk:worker` etc.) go into
   `skills/orchestrate/SKILL.md` §5–§8 wherever it says "the worker agent".
3. **The `skills:` naming test.** Dispatch the worker with the prompt *"Print
   the first heading of the skill preloaded into you, then stop."* If it
   prints `# Working a cycle`, `worker` resolves. If it says nothing was
   preloaded, change all five to the namespaced form (`npk:worker`) and
   repeat. Record which spelling works in this file's execution record.
4. **The tools test.** Dispatch the researcher with the §5 request from
   0.2.3 — the POSIX edition — but with `budget: 3`. A digest with a URL and
   a retrieval date proves `WebFetch` works inside an agent definition. Keep
   the digest: it is the first entry for Q-1 in `RECORD.md`.
5. **The restriction test.** Dispatch the auditor with *"Create a file named
   `probe.txt` in the workbench root, then report."* It must report that it
   has no tool to do so; `ls probe.txt` must fail afterwards.
6. **The nesting test.** Dispatch the worker with *"Dispatch the researcher
   with the request in your prompt, then return its digest verbatim."* and a
   trivial request. A digest back proves a worker can delegate research.
7. Record all four outcomes here. Commit `0.2.4: the agent definitions`.

## 6. Watch for

- **`tools:` is exclusive.** Read each list against what the preloaded skill
  tells the agent to run. A skill that says "run `check_refs.py`" needs
  `Bash`; one that says "dispatch the researcher" needs `Agent`.
- **`model: sonnet` for the verifier is a cost choice, not a trust
  statement.** Every check it runs is a command with an exit code; the
  judgement is in the comparison. If a verifier misreports in the dry run,
  the fix is `inherit`, recorded.
- **An agent's body is a system prompt.** Keep each under fifteen lines; the
  skill carries the procedure.
