# 0.2.5 — the guard — PLANNED

> The guard is right about what it checks and wrong about where it stands. It
> self-scopes on the hook's `cwd`, which follows the shell's `cd`, so a `cd`
> into the compiler tree — allowed, as a read — disarms it for the next call.
> Today the harness resets the directory on leaving the project root, which
> closes the hole by accident and is not something to depend on. This
> subcycle scopes the guard on the session's project directory, handles `cd`
> anywhere in a command, makes the claim protocol a mechanism, and takes the
> home paths out of a public repository.

## 1. Where you are

`tools/guard_compiler_tree.py` (about 200 lines) and `tools/test_guard.py`
(45 cases, all passing). The guard is installed in `~/.claude/settings.json`
as a `PreToolUse` hook on `Bash|Write|Edit|NotebookEdit` — that entry does
not change, because the file path does not change.

## 2. Decisions

P-15. Local:

- **L-1 — the claim rule keys on the board's stream tables.** A repository
  is claimed when a line of `BOARD.md` that begins with `|` contains its
  backticked name and the word `CLAIMED`. *Why:* the stream tables are what a
  reader reads; a hidden machine-readable block would drift from them.
  *Declined:* a separate claims file (two homes).
- **L-2 — a session started inside a repository is exempt from that
  repository's claim rule**, exactly as a compiler session is exempt from the
  compiler rule. The author's ad-hoc sessions in a library keep working. A
  session started in the *workbench* that wants to edit a library claims it
  on the board first; the workbench `CLAUDE.md` (0.2.6) says so.
- **L-3 — paths come from the environment with the current values as
  defaults**, via `os.path.expanduser`, so no tracked file carries `/home/`.
  The tests set the variables to a fixture directory.

## 3. The changes to `guard_compiler_tree.py`

1. **Configuration.**
   ```python
   COMPILER  = realpath(env("NPK_COMPILER_DIR", "~/Workspace/REPOS/nitpick"))
   LIBS      = realpath(env("NPK_LIBS_DIR",     "~/Workspace/REPOS/nitpick-libs"))
   APPS      = realpath(env("NPK_APPS_DIR",     "~/Workspace/REPOS/nitpick-apps"))
   BOARD     = LIBS + "/BOARD.md"
   ```
2. **Self-scoping on the project directory.** `project = realpath(env
   CLAUDE_PROJECT_DIR)` if set, else the hook input's `cwd`. The compiler
   rule is skipped when `project` is inside `COMPILER`. The per-call `cwd`
   is still what relative targets resolve against, because it is what the
   shell will use.
3. **`cd` anywhere.** Split the command on `&&`, `||`, `;` and `|` into
   segments (outside quotes — `shlex` with `punctuation_chars=True` gives
   this), walk them in order, and let a segment `cd X` or `pushd X` move the
   effective directory for the segments after it. Replace the two
   leading-`cd` special cases with this.
4. **The claim rule.** After the compiler check, for every write target:
   find whether it lies under `<LIBS>/<name>/` or `<APPS>/<name>/` where
   that directory contains `.git`. If so, and `project` is not inside that
   directory, read `BOARD.md` and require a line starting `|` that contains
   `` `<name>` `` and `CLAIMED`. Otherwise deny with:
   > Refused: a write into `<name>`, which no stream has claimed on
   > BOARD.md. One writer per repository (W-7): the orchestrator claims a
   > repository on the board before anyone writes to it. If you are working
   > in this repository by hand, start the session inside it.
   A mutating `git -C <dir> …` counts as a write into `<dir>`.
5. **The workbench-writer rule (P-19).** For a write target under a
   workbench root that is *not* inside a repository subdirectory — the
   board, the record, the playbook, the skills — read the board's
   `Workbench writer:` line. `none`, or a session id equal to the hook
   input's `session_id`, allows. Any other id denies:
   > Refused: the board names another session as the workbench's writer.
   > One writer here (W-16). If that session is gone, set the line to
   > `none` on the board from the session that owns it, or by hand.
   A session started inside the workbench is *not* exempt, because every
   session here starts inside it.
6. **Everything else unchanged**, including the heredoc stripping and the
   source-versus-destination distinction. Run the 45 existing cases before
   touching the tests.

## 7. Watch for

- **The guard runs on every tool call of every session on this machine.**
  Reading a 5 KB board per call is fine; anything slower is not. Keep it
  under fifty milliseconds — time it with the test.
- **`shlex` with `punctuation_chars` changes tokenisation.** The redirection
  regex runs on the raw command text as before; only the segment walk uses
  the new tokens. Keep the two apart.
- **A false positive gets the guard disabled.** Every new blocking case
  needs an allowing twin, as the table above has.
- **`CLAUDE_PROJECT_DIR` is set by the harness, not by the shell.** The test
  sets it explicitly; do not rely on inheriting it.
