# 0.2.6 — survival: compaction, loading, the workbench `CLAUDE.md` — DONE (2026-09-03)

> An orchestrator that runs for days outlives its context window. After
> compaction the pasted prompt and the loaded skill may survive only as a
> summary, and nothing at the workbench root tells a session what it is. A
> plugin loaded by a flag is lost the day the flag is forgotten. This subcycle
> makes the orchestrator's rules survive compaction, gives the workbench a
> `CLAUDE.md`, and loads the plugin without the flag.

The orchestrate skill (0.2.2) writes `.internal/orchestrator.session` at
startup. `hooks/` does not exist and is un-ignored. There is no `CLAUDE.md`
at the workbench root — every library has one, the compiler has one, the

## 3. `tools/reinject_orchestrator.py` and `hooks/hooks.json`

The script reads the hook JSON from stdin, takes `session_id`, resolves the
workbench as `NPK_LIBS_DIR` or the default, and if
`<libs>/.internal/orchestrator.session` exists and equals the session id,
prints exactly:

```
ORCHESTRATOR — context restored after compaction or resume.
You are the orchestrator for the Nitpick ecosystem, in nitpick-libs.
Procedure: skills/orchestrate/SKILL.md (the loop §5, on a report §7, the stop
list §9). Live state: BOARD.md. Past: RECORD.md.
Before any further action:
  1. re-read BOARD.md;
  2. run ListAgents and reconcile the in-flight table — a row with no live
     agent is stale, §4 Recovery;
  3. do not redo what the board shows done: the pin, the claims, the
     questions already on the table;
  4. width and streams are the board's header, not your memory.
Then continue the loop.
```

Nothing otherwise. `hooks/hooks.json`:

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "compact|resume",
        "hooks": [
          { "type": "command",
            "command": "python3 ${CLAUDE_PLUGIN_ROOT}/tools/reinject_orchestrator.py",
            "timeout": 5 }
        ]
      }
    ]
  }
}
```

The orchestrate skill's clean stop (nothing left to dispatch, batch sent)
removes the marker; a session that ends otherwise leaves it, which is
harmless because the next session has a different id.

**Test:** in a workbench session, write the marker with that session's id
(`${CLAUDE_SESSION_ID}`), run `/compact`, and confirm the block appears in
the restored context. Then in a second session with a different id, `/compact`
must add nothing.

## 4. The workbench `CLAUDE.md`

Under forty lines, at the root:

```
# CLAUDE.md — the library workbench

What this is: the shared documents and the working system (the `npk`
plugin) for the Nitpick libraries. Each subdirectory is a library checkout
with its own history; this repository tracks the root only.

Who you are:
- started here with `/npk:orchestrate` → the orchestrator. The loop is
  skills/orchestrate/SKILL.md; the live state is BOARD.md; the past is
  RECORD.md. You write here and nowhere else.
- an agent dispatched by the orchestrator → your skill is preloaded and your
  prompt carries your inputs. You write only under your REPO.
- the author, or a session here for anything else → read BOARD.md first.

Write rules, enforced where they can be:
- the compiler at ../nitpick is READ-ONLY from here (the guard refuses writes)
- a library or application repository is written only when BOARD.md shows it
  CLAIMED, or by a session started inside it (the guard refuses the rest)
- this repository has one writer, the orchestrator (W-16); BOARD.md's header
  names it — if it names a session that is not you, do not write here. The
  board itself is the lock: take it only when that session is gone, and
  record the takeover in RECORD.md

Read first: README.md (the map), WORKSTREAMS.md (the rules W-1…W-26),
PLAYBOOK.md (what the language imposes). The plan for the system itself is
meta/roadmap/.

If your context was compacted: re-read BOARD.md before acting.
```

## 8. Watch for

- **`SessionStart` output goes into the context as text.** Keep the block
  short and imperative; it is read by a model mid-task.
- **The hook fires for every session with the plugin loaded**, in any
  directory. The marker check is what keeps it silent elsewhere; test the
  silent case, not just the loud one.
- **The symlink is a write outside this repository.** It is the author's to
  make; the plan does not make it.
- **The marker must hold the id the hook sees.** 0.2.5 established that the
  hook's `session_id` is the UUID form (the transcript's name), that the
  Bash tool's environment carries neither `CLAUDE_SESSION_ID` nor
  `CLAUDE_PROJECT_DIR`, and that only substitution in skill text supplies
  the former. The compaction test in §3 is what proves the two agree.
